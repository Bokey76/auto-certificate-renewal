# 源码说明

入口是 `src/cli.ts`，编译后是容器里的 `cert-renew`。任务串行执行。阿里云 SDK、Certbot、Nginx 都通过注入的接口调用，测试里换成假实现。

```text
cli.ts          解析命令：run / schedule / web / dns-auth / dns-cleanup
  schedule-loop.ts  时刻表：暂停、再跑一轮、心跳
  runner.ts     决定签发、跳过、重试，按顺序调用下面各步
    config.ts   读 YAML、校验字段、填默认值
    certbot.ts  拼 Certbot 参数并执行
    dns-hook.ts Certbot 回调：写/删阿里云 TXT
    nginx.ts    备份、写证书、nginx -t、reload、失败还原
    cdn.ts      上传 CAS、按域名绑定、按指纹跳过重复上传
    hook.ts     新签发后跑一条 shell
    state.ts    读写 state/<id>.json、status.json
  web.ts        状态页和三个按钮
    overview.ts 把配置、状态、心跳和日志末尾收成一页
    control.ts  暂停标记、再跑一轮、scheduler.json
```

数据目录默认 `/var/lib/acme`：`letsencrypt/` 是 Certbot 账户和 live 证书，`state/` 是每条任务状态，`status.json` 是最近一轮汇总，`logs/` 是按时间戳切开的日志，`dns-records/` 是这一轮创建的 TXT 记录 ID。`control/paused` 表示暂停定时检查，`control/run-request` 表示还要再跑一轮，`scheduler.json` 是调度进程心跳。网页不读 `letsencrypt/`。

## 模块和导出函数

### `cli.ts`

进程入口。读当前目录 `.env`，再按子命令分发。无子命令时当作 `run`。镜像的 CMD 是 `schedule`。

| 函数 | 作用 |
| --- | --- |
| `executeRun` | 读配置、建日志，调用 `runAll`。根配置失败返回 1 |
| `schedule` | 交给 `runScheduleLoop`。未暂停时先跑一轮；退出码 1 则结束进程 |
| `serveWeb` | 口令至少 12 位，然后监听状态页。口令太短或端口不合法时退出 |
| `readFlags` | 解析 `--job`、`--dry-run` |

### `schedule-loop.ts` / `control.ts`

| 函数 | 作用 |
| --- | --- |
| `decide` | 决定这一拍是启动跑、到点跑、消费一次再跑、跳过这一档，还是继续等 |
| `runScheduleLoop` | 每 5 秒醒一次。长跑期间仍写心跳。偏移在进入一段等待时抽一次 |
| `setPaused` / `isPaused` | 创建或删除 `control/paused` |
| `requestRun` / `consumeRunRequest` | 记下或取走一次 `control/run-request`。已有请求时不覆盖 |
| `writeScheduler` / `readScheduler` | 原子写心跳。坏 JSON 视为不在线 |
| `schedulerOnline` | 心跳时间与当前时刻相差不超过 20 秒 |

### `overview.ts` / `web.ts`

| 函数 | 作用 |
| --- | --- |
| `loadOverview` | 拼出这一台机器的页面数据。配置读不了时任务表为空 |
| `readLogTail` | 只读 `status.json` 指向的、且位于 `logs/` 下的日志末尾，最多 200 行、64KB |
| `startWeb` | 登录、会话、`/api/overview`、暂停、恢复、立即检查。不接收日志路径或命令 |

### `runner.ts`

| 函数 | 作用 |
| --- | --- |
| `runAll` | 按配置顺序跑全部（或 `--job` 指定的）任务，写 `status.json`，返回退出码 |
| `runJob` | 单条：跳过 / 签发 / 应用 / 钩子。一条抛错不影响后面的任务 |
| `selectJobs` | 按 id 过滤合法任务和非法任务 |
| `hasFailedApply` / `actionHealthy` | 看状态文件里 Nginx 路径或 `cdn:<域名>` 是否上次成功 |
| `finish` | 写出本轮 `status.json` |

签发条件：演练、没有 live 证书、进入 `renewBeforeDays` 窗口、或上次 `lastIssueError` 有值。演练成功不改任务状态、不应用。证书指纹变了才算新签发，钩子只在这时跑。

### `config.ts`

| 函数 | 作用 |
| --- | --- |
| `loadConfig` | 读 YAML。根失败返回 `{ ok: false }`；单条任务失败放进 `invalidJobs`，其余照常。`schedule.hours` 省略则为 `[3, 15]` |
| `nginxDestination` | 把宝塔 `certDir` 或 custom 路径收成统一的 fullchain / privkey / bin |

### `certbot.ts`

| 函数 | 作用 |
| --- | --- |
| `buildCertbotArgs` | 拼 `certonly` 参数。HTTP-01 用 webroot；DNS-01 用 manual + 本程序的 dns 钩子 |
| `certbotEnv` | 给 DNS 钩子准备 `CERT_RENEW_ZONE` 等环境变量 |
| `runCertbot` | 执行 Certbot，超时 15 分钟 |
| `lineageExists` | 是否已有该 id 的 renewal 配置或 live 目录。有则续签时加 `--force-renewal` |
| `certbotFailure` | 把 stdout/stderr 收成失败原因 |

已有 lineage 且不是演练时加 `--force-renewal`，续签窗口由本程序的 `renewBeforeDays` 决定，不沿用 Certbot 自己的 30 天。

### `dns-hook.ts` / `dns-names.ts`

| 函数 | 作用 |
| --- | --- |
| `txtRecord` | 由 Certbot 域名和 `zone` 算出阿里云 RR 和 FQDN |
| `dnsAuth` | 添加 TXT，记下 RecordId；`CERTBOT_REMAINING_CHALLENGES` 为 0 时等待传播 |
| `dnsCleanup` | 只删除本轮、本 FQDN、本校验值对应的那条记录 |
| `credentialFromHookEnv` | 钩子进程里按 `CERT_RENEW_CREDENTIAL` 取密钥 |

### `nginx.ts`

| 函数 | 作用 |
| --- | --- |
| `applyNginx` | 备份 → 写入 → `chmod` → `nginx -t` → reload。测试或 reload 失败还原备份；reload 失败后再 reload 一次回到旧证书 |
| `livePaths` | Certbot live 目录下该任务的 fullchain / privkey 路径 |

默认通过 `nsenter -t 1 -m` 进宿主机 mount 命名空间再执行 nginx 二进制。

### `cdn.ts`

| 函数 | 作用 |
| --- | --- |
| `applyCdn` | 检查覆盖 → 指纹未变则复用 CertId → 否则上传 → 逐个绑定。已成功的域名在同指纹下跳过 |
| `cdnTargetKey` | 状态键 `cdn:<小写域名>` |
| `uploadWithUniqueName` | 名称冲突时尝试 `-2` … 最多 5 次 |

### `hook.ts` / `expiry.ts` / `schedule.ts` / `state.ts`

| 函数 | 作用 |
| --- | --- |
| `runHook` | `/bin/sh -c <command>`，超时按秒 |
| `readCertificate` | 读 PEM 第一张证书的指纹、到期、SAN |
| `nameCovered` | 域名是否被 SAN 覆盖；泛域名只覆盖下一级 |
| `withinRenewWindow` | `notAfter - now <= renewBeforeDays` |
| `nextRun` | 时区内下一次配置小时加上本次分钟偏移 |
| `randomOffsetMinutes` | 现抽 0–30，不写盘 |
| `readJobState` / `writeJobState` | 每条任务的指纹、目标成败、CAS CertId |
| `writeStatus` | 本轮汇总，写入 `status.json` |

### `aliyun.ts` / `env.ts` / `exec.ts` / `log.ts`

| 函数 | 作用 |
| --- | --- |
| `createAliyunClients` | 按区域和可选 credential 名构造 CAS / CDN / DNS 客户端 |
| `loadDotEnv` | 读 `.env`，已有环境变量不覆盖 |
| `alibabaCredential` | 取默认或 `_NAME` 后缀那一组密钥 |
| `spawnExec` | 跑子进程，可超时杀掉 |
| `nginxArgv` | 默认加上 `nsenter`；`CERT_RENEW_DIRECT_NGINX=1` 时直接跑 |
| `createLogger` | 一行日志同时写 stdout 和文件，格式 `时间 [任务id] 内容` |

### `types.ts`

领域类型：配置、任务状态、`status.json`、以及可注入的 `Exec` / `CertificateService` / `CdnService` / `DnsService`。测试实现这些接口，不打真实网络。
