# 使用说明

概览和最快开始见仓库根目录 [README.md](../README.md)。字段见 [配置.md](配置.md)。一轮里如何换证见 [执行流程.md](执行流程.md)。

推荐在开发机构建镜像、推到阿里云容器镜像服务，服务器只拉镜像跑。服务器上也可以对着 Dockerfile 现场构建。

## 本机构建并推到阿里云

镜像里只有 Node、Certbot、`nsenter` 和程序。密钥、域名、宝塔路径因机器而异，不要打进镜像。服务器上用三份本地文件把容器跑起来：`docker-compose.yml`、`config/config.yaml`、`.env`。不必放源码。

Windows 用 Docker Desktop 的 **Linux 容器**。构建架构要和服务器一致，常见 x86_64 用 `linux/amd64`；ARM 服务器改成 `linux/arm64`。

仓库地址从容器镜像服务控制台复制。`login`、`build -t`、`push`、compose 的 `image`、服务器 `docker login` **必须是同一段地址**。个人版形如 `crpi-xxxxxxxx.cn-shenzhen.personal.cr.aliyuncs.com`，企业版域名不同。把 `<ACR域名>`、`<命名空间>`、版本号换成你自己的，不要把真实实例 ID 写进公开仓库。构建时直接打 tag，不要先 `build` 再拿 ImageId 去 `docker tag`。

```bash
REGISTRY=<ACR域名>
IMAGE=$REGISTRY/<命名空间>/auto-certificate-renewal:0.1.0

# 用户名是阿里云账号，密码用 ACR 固定密码或临时密码
docker login --username=<阿里云账号> $REGISTRY
docker build --provenance=false --sbom=false --platform linux/amd64 -t $IMAGE .
docker push $IMAGE
```

PowerShell 里把 `$REGISTRY` / `$IMAGE` 换成具体字符串即可。

### 服务器上第一次跑

在服务器建一个小目录（例如 `/opt/cert-renew`），只放这三份文件：

1. `docker-compose.yml`：`image` 写成上面的 `$IMAGE` 全名，**不要写 `build: .`**
2. `config/config.yaml`：从仓库的 `config/config.example.yaml` 复制后改域名和路径
3. `.env`：从仓库的 `.env.example` 复制后填 AccessKey

`docker-compose.yml` 示例：

```yaml
services:
  renew:
    image: <ACR域名>/<命名空间>/auto-certificate-renewal:0.1.0
    command: ["cert-renew", "schedule"]
    pid: host
    privileged: true
    env_file:
      - .env
    volumes:
      - ./config/config.yaml:/config/config.yaml:ro
      - acme-data:/var/lib/acme
      - /www/server/panel/vhost/cert:/www/server/panel/vhost/cert
      - /var/www/acme:/var/www/acme
    restart: unless-stopped

volumes:
  acme-data:
```

只做 DNS-01 和 CDN、这台机器没有 Nginx 时，去掉证书目录和 webroot 两行挂载。HTTP-01 需要 webroot。宝塔证书目录通常挂 `/www/server/panel/vhost/cert`。自装 Nginx 把 `fullchainPath` / `privkeyPath` 所在目录挂进去。

在该目录执行：

```bash
docker login --username=<阿里云账号> <ACR域名>
docker compose pull
docker compose up -d
docker compose logs --tail=100 renew
```

镜像默认命令是 `cert-renew schedule`：起来先跑一轮，再按时刻表循环。立刻再跑一轮或演练：

```bash
docker compose run --rm --entrypoint cert-renew renew run
docker compose run --rm --entrypoint cert-renew renew run --dry-run
```

停掉：`docker compose down`。数据卷 `acme-data` 还在，Let’s Encrypt 账户和本地证书不会丢。

### 以后只更新镜像

本机改版本号再 `build` / `push`。服务器上还是那三份文件，只把 compose 里的 tag 改成新版本（若 tag 固定为 `0.1.0` 被覆盖，则不用改文件）：

```bash
docker compose pull
docker compose up -d
```

改域名或密钥：只改服务器上的 `config.yaml` / `.env`，然后 `docker compose up -d`。不必重新构建镜像。

## 在服务器上现场构建

仓库和配置都在这台 Linux 上时：

```bash
cp config/config.example.yaml config/config.yaml
cp .env.example .env
# 编辑这两份后再启动
docker compose up -d --build
```

仓库里的 `docker-compose.yml` 使用 `image: auto-certificate-renewal:local` 和 `build: .`，就是这条路径。

## 启动之后

默认命令是 `cert-renew schedule`：

1. 容器每次启动立刻跑一轮。
2. 按 `TZ`（默认 `Asia/Shanghai`）在 `schedule.hours`（默认 03:00 和 15:00）附近再跑。每次睡前现抽 0–30 分钟偏移，不写数据卷，多台机器自然错开。一轮结束后日志会写「下次检查」和本次偏移。
3. 根配置读不了（退出码 1）时进程退出，方便 compose 重启后重新读挂载。有任务失败（退出码 2）时继续按时刻表跑。

`pid: host` 和 `privileged: true` 是为了用 `nsenter` 调用宿主机 nginx。HTTP-01 / DNS-01 都不需要 `network_mode: host`。

## 命令

下面都在放 `docker-compose.yml` 的目录里执行。`<任务id>` 换成配置里的 `jobs[].id`，例如 `www-example`。

| 目的 | 命令 |
| --- | --- |
| 正常跑起来（后台时刻表） | `docker compose up -d` |
| 看是否在跑 | `docker compose ps` |
| 看日志 | `docker compose logs --tail=200 renew` |
| 立刻跑全部任务一次 | `docker compose run --rm --entrypoint cert-renew renew run` |
| 只跑一条 | `docker compose run --rm --entrypoint cert-renew renew run --job <任务id>` |
| 演练，不改 Nginx / CDN | `docker compose run --rm --entrypoint cert-renew renew run --dry-run` |
| 只演练一条 | `docker compose run --rm --entrypoint cert-renew renew run --job <任务id> --dry-run` |
| 重启（起来会立刻再跑一轮） | `docker compose restart` |
| 停止，容器还在，数据卷还在 | `docker compose stop` |
| 停掉并删容器，数据卷还在 | `docker compose down` |

镜像里的子命令是 `cert-renew schedule`（默认）、`cert-renew run`、`cert-renew run --job <任务id>`、`cert-renew run --dry-run`。`dns-auth` / `dns-cleanup` 是 Certbot 的钩子，不要手工调用。

`up -d` 才是长期自动续签。`run` 是额外做一轮，跑完就退出，不会关掉正在跑的时刻表容器。时刻表那一轮正在写证书时，不要再开一个 `run`。

`--dry-run` 不替换 Nginx、不调 CDN、不跑命令钩子。DNS-01 演练时 Certbot 仍可能向阿里云解析写 TXT。第一次对真实域名联调，把 `letsencrypt.staging` 设为 `true`。

不要用 `docker compose down -v`。`-v` 会删掉 `acme-data`，Let’s Encrypt 账户和已签证书一起没了。

退出码：`0` 全部成功或跳过；`1` 配置读不了；`2` 至少一条任务失败。

## 本机单元测试

需要 Node.js 24.22.1 或同一条 24 线上的更高版本。目录里有 `.nvmrc`。

```bash
nvm use
npm ci

```

## 怎么确认续签和 CDN 已经更新

```bash
docker compose logs --tail=200 renew
docker compose exec renew cat /var/lib/acme/status.json
docker compose exec renew cat /var/lib/acme/state/www-example.json
```

日志结束有一行汇总：总数、跳过、成功、失败。跳过会写「证书仍在续签窗口外」。签发成功会写「签发成功」，随后是 Nginx 和 CDN 的成败。

`status.json`：`exitCode`、`finishedAt`、每条任务的 `status` / `notAfter` / `error`，以及 Nginx 的 `nginxTest`、`nginxReload`。

`state/<任务id>.json`：

- `fingerprint`、`notAfter`、`lastIssuedAt`
- `cas.certId`、`cas.name`（形如 `acme-www-example-20261027`）
- `targets["cdn:example.com"].ok` 为 `true` 表示该加速域名已用这个 CertId 绑定成功

再到阿里云控制台：数字证书管理服务里出现对应名称的用户证书；CDN 该域名 HTTPS 已开启，证书类型为 CAS，CertId 与状态文件一致。

从外面看证书：

```bash
echo | openssl s_client -servername www.example.com -connect www.example.com:443 2>/dev/null | openssl x509 -noout -dates -fingerprint -sha256
```

指纹应与状态文件里的 `fingerprint` 一致，到期时间接近 `notAfter`。

证书还很新时时刻表只会跳过。测试环境要把 `staging` 设为 `true`，并把 `renewBeforeDays` 临时改成大于剩余天数（例如 `120`），然后 `cert-renew run`。测完改回 `30`，正式签发前把 `staging` 改回 `false`。不要频繁对正式环境强制续签，Let’s Encrypt 有每周配额。
