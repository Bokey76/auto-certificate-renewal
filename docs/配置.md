# 配置说明

程序在**容器内**默认读取 `/config/config.yaml`。仓库里提交的是模板，本机要先复制再改。先配什么、一轮怎么跑见 [执行流程.md](执行流程.md)。

```text
仓库模板    config/config.example.yaml
本机配置    config/config.yaml              （已被 git 忽略）
容器内      /config/config.yaml             compose 挂载
密钥        .env                            （已被 git 忽略）
密钥模板    .env.example
```

```bash
cp config/config.example.yaml config/config.yaml
cp .env.example .env
```

改 `config/config.yaml` 里的域名、校验方式和 `apply`。改 `.env` 里的阿里云密钥和时区。密钥不要写进 YAML。

改容器内配置路径时，在 `.env` 设 `CONFIG_PATH`。数据目录默认 `/var/lib/acme`，可用 `CERT_RENEW_DATA_DIR` 改。

## 根字段

| 字段 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `serverName` | 否 | 主机名 | 写进 `status.json`，第二期控制机用来认这台机器 |
| `letsencrypt` | 是 | | Let’s Encrypt 相关 |
| `letsencrypt.email` | 是 | | 注册邮箱，必须含 `@` |
| `letsencrypt.staging` | 否 | `false` | `true` 走测试环境，证书不被浏览器信任，联调用这个 |
| `letsencrypt.renewBeforeDays` | 否 | `30` | 剩余有效期少于此天数（含）才签发。必须是大于 0 的整数 |
| `letsencrypt.keyType` | 否 | `ecdsa` | 私钥算法，见下面「keyType」。只能是 `ecdsa` 或 `rsa` |
| `alibaba` | 否 | | 可整段省略 |
| `alibaba.regionId` | 否 | `cn-shenzhen` | 阿里云地域 |
| `schedule` | 否 | | 可整段省略 |
| `schedule.hours` | 否 | `[3, 15]` | 时区内每天检查的小时，0–23 的整数，至少一个。只写 `[3]` 就是每天一次；`[1, 12]` 就是 01:00 和 12:00 附近。重复项会去掉。每次睡前再随机加 0–30 分钟，不写盘 |
| `jobs` | 是 | | 任务数组。根不是映射、YAML 解析失败、`jobs` 不是数组、`schedule.hours` 不合法时整份失败，退出码 1 |

### keyType

整份配置共用一个私钥类型，默认 `ecdsa`。已经签发过的任务要换类型时，下一轮真正续签才会换成新私钥。

| 值 | Certbot 参数 | 怎么选 |
| --- | --- | --- |
| `ecdsa` | P-256（`secp256r1`） | 默认。证书和握手更短，宝塔 Nginx、阿里云 CDN、当前浏览器都支持 |
| `rsa` | 2048 位 | 要对接明确不支持 ECDSA 的旧客户端或旧设备时再用 |

两种都是 Let’s Encrypt 正式证书，浏览器信任程度相同。没有兼容性要求就留 `ecdsa`。

## 一条任务

| 字段 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `id` | 是 | | 1–40 位小写字母、数字、连字符，不能以连字符开头或结尾。同时是 Certbot 证书名和 `state/<id>.json` 的文件名。同一文件内不能重复 |
| `enabled` | 否 | `true` | `false` 记为跳过。字段不合法时即使停用也记失败 |
| `domains` | 是 | | 至少一个。允许 `*.example.com`。出现泛域名时 `challenge.type` 必须是 `dns-01` |
| `challenge` | 是 | | 见下表 |
| `credential` | 否 | 默认密钥 | 只含字母和数字。`prod` 读取 `.env` 里带 `_PROD` 后缀的那一组 |
| `apply` | 否 | `[]` | 应用动作。可省略，证书只留在数据卷 |
| `hook` | 否 | | 仅在这一轮真正写出新证书后执行 |

### challenge

两条都是向 Let’s Encrypt 证明「这个域名是你的」。一张证书只能选一种。有泛域名时必须是 `dns-01`。

| | HTTP-01 | DNS-01 |
| --- | --- | --- |
| 怎么证明 | Let’s Encrypt 从公网访问 `http://域名/.well-known/acme-challenge/…` | 在阿里云解析里写 `_acme-challenge` TXT，验证完删除 |
| 适合 | 域名的 80 端口直接打到这台源站 Nginx | 前面有 CDN、要签泛域名、这台机器不对外提供该域名的 HTTP |
| 不适合 | 泛域名；CDN 或防火墙挡住 80 端口 | 域名不在阿里云云解析上 |
| 要先准备 | webroot 挂进容器，Nginx 配好校验 location | `.env` 里的云解析权限，以及 `zone` |
| 会改什么 | 只在 webroot 写临时文件 | 临时 TXT。不改 Nginx、不改 CDN |

域名已经走 CDN 时用 DNS-01。HTTP-01 只有确认 Let’s Encrypt 能直达源站 80 端口时再用。

**HTTP-01**

```yaml
challenge:
  type: http-01
  webroot: /var/www/acme   # 可省略，默认就是这个路径
```

容器把校验文件写到 `webroot`。宿主机 Nginx 必须能用 HTTP 提供 `/.well-known/acme-challenge/`，并且该目录已挂进容器。宝塔会重写站点主配置，这段放到扩展目录，例如 `/www/server/panel/vhost/nginx/extension/<域名>/acme.conf`：

```nginx
location ^~ /.well-known/acme-challenge/ {
    default_type text/plain;
    alias /var/www/acme/;
}
```

`alias` 必须和本条任务的 `webroot` 是同一宿主机目录。

**DNS-01**

```yaml
challenge:
  type: dns-01
  zone: example.com          # 阿里云解析里的主域名，必填，程序不猜根域
  propagationSeconds: 60     # 0–3600，最后一个 TXT 写完后等待的秒数
```

主机记录由域名和 `zone` 算出：`example.com` → `_acme-challenge`；`www.example.com` 且 zone 为 `example.com` → `_acme-challenge.www`。同一名称上可以有多条 TXT（例如同时签 `example.com` 和 `*.example.com`）。

### apply：Nginx 宝塔

```yaml
- type: nginx
  kind: baota
  certDir: /www/server/panel/vhost/cert/example.com
  # fullchainName: fullchain.pem    # 可省略
  # privkeyName: privkey.pem
  # nginxBin: /www/server/nginx/sbin/nginx
```

只替换 `certDir` 下的证书文件，不改 server 块，不写宝塔数据库。`nginx -t` 通过后才 reload；失败会还原备份。

应用 Nginx 时，`certDir` 不存在会按路径建出来（包含中间目录）。`--dry-run` 不会建。目录建在容器看到的路径上，所以父目录必须已经挂进容器（宝塔一般挂 `/www/server/panel/vhost/cert`）。建目录不会改站点配置：`ssl_certificate` 必须事先指向这里的 `fullchain.pem` / `privkey.pem`，否则 Nginx 不会用这份新证书。

### apply：自装 Nginx

```yaml
- type: nginx
  kind: custom
  fullchainPath: /etc/nginx/ssl/api.example.com/fullchain.pem
  privkeyPath: /etc/nginx/ssl/api.example.com/privkey.pem
  nginxBin: /usr/sbin/nginx          # 必填
```

站点配置里的证书路径要事先写成这两条路径。

### apply：阿里云 CDN

```yaml
- type: aliyun-cdn
  domainNames:
    - example.com
    - www.example.com
```

加速域名必须已经在 CDN 上存在并开通 HTTPS。程序不创建域名。每个名字必须被本证书覆盖（精确相等，或被证书里的一级泛域名覆盖）。先上传到数字证书管理服务，再用返回的 CertId 绑定。名称形如 `acme-<任务id>-YYYYMMDD`。

### hook

```yaml
hook:
  command: /hooks/after-issue.sh
  timeoutSeconds: 60          # 1–300，默认 60
```

容器内用 `/bin/sh -c` 执行。仅新签发后跑。失败不回滚已经完成的 Nginx / CDN。环境变量：`CERT_JOB_ID`、`CERT_DOMAINS`、`CERT_LIVE_DIR`、`CERT_FULLCHAIN`、`CERT_PRIVKEY`、`CERT_NOT_AFTER`。

## `.env`

| 变量 | 说明 |
| --- | --- |
| `TZ` | 时刻表时区，默认 `Asia/Shanghai` |
| `ALIBABA_CLOUD_ACCESS_KEY_ID` | 默认 AccessKey |
| `ALIBABA_CLOUD_ACCESS_KEY_SECRET` | 默认 Secret |
| `ALIBABA_CLOUD_ACCESS_KEY_ID_<NAME>` | 任务写了 `credential: name` 时用这一组，NAME 为大写 |
| `CONFIG_PATH` | 容器内配置路径，默认 `/config/config.yaml` |
| `CERT_RENEW_DATA_DIR` | 数据卷路径，默认 `/var/lib/acme` |
| `CERTBOT_BIN` | Certbot 可执行文件，默认 `certbot` |
| `CERT_RENEW_DIRECT_NGINX` | 设为 `1` 时不经 `nsenter`，直接跑 nginx（测试用） |

RAM 用户按实际用到的能力授权：云解析记录读写、`yundun-cert:UploadUserCertificate`、`cdn:SetCdnDomainSSLCertificate`。

## 一条任务怎么被处理

1. 字段不合法：记失败，下一条继续。
2. `enabled: false`：跳过。
3. 证书剩余时间多于 `renewBeforeDays`，并且 Nginx / CDN 上次都成功：跳过。
4. 证书缺失、进入续签窗口、或上次签发失败：调用 Certbot。
5. 证书没变、只有应用动作失败：不签发，只重试失败的动作。
6. `apply` 按书写顺序执行。一个失败，后面的继续。
7. 这一轮 Certbot 真正写出新证书时才跑钩子。

整份 YAML 读不了或根字段不合法：退出码 1，不写 `status.json`。有任务失败：退出码 2。全部成功或跳过：0。
