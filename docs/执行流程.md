# 执行流程

程序按配置检查证书，需要时调用 Certbot 签发，再把新证书写到 Nginx 文件并绑定阿里云 CDN。站点 server 块、CDN 域名、解析和密钥都要人先准备好。

字段含义见 [配置.md](配置.md)，启动和镜像见 [使用.md](使用.md)。

## 人工必须先准备好的

程序不会创建站点、不会改 Nginx 配置、不会开通 CDN、不会申请阿里云账号。

| 要先做好 | 为什么 |
| --- | --- |
| 服务器已装 Docker，容器能出站访问 Let’s Encrypt 和阿里云 API | 签发和换证都在容器里发起 |
| `config/config.yaml` 和 `.env` | 域名、任务、密钥。密钥不要写进 YAML |
| 域名解析在阿里云云解析（用 DNS-01 时） | 程序只向这套解析写 `_acme-challenge` TXT |
| 宝塔（或自装 Nginx）站点已经存在，并且已经按 HTTPS 配好 | 程序只替换 pem，不写 `listen 443` 和 `ssl_certificate` |
| 站点配置里的证书路径等于任务里的 `certDir`（或 custom 的两条路径） | 路径不一致时，reload 后 Nginx 仍读旧文件 |
| compose 已挂上证书目录（宝塔通常是 `/www/server/panel/vhost/cert`） | 容器通过 bind 把新 pem 写到宿主机 |
| 要用 HTTP-01 时：80 端口由**源站** Nginx 提供 `/.well-known/acme-challenge/`，webroot 已挂进容器 | 前面若是 CDN，Let’s Encrypt 打到的是 CDN，HTTP-01 常失败；优先 DNS-01 |
| 阿里云 CDN 加速域名已经存在，并且已经开通 HTTPS | 程序不创建 CDN 域名，只上传证书再绑定 |
| RAM 权限：云解析记录读写、`yundun-cert:UploadUserCertificate`、`cdn:SetCdnDomainSSLCertificate` | 缺权限时 DNS / CAS / CDN 会失败 |
| `pid: host` 和 `privileged: true`（本机要 reload Nginx 时） | 容器用 `nsenter` 跑宿主机上的 nginx 二进制 |

宝塔站点配置里应已经是：

```nginx
ssl_certificate      /www/server/panel/vhost/cert/example.com/fullchain.pem;
ssl_certificate_key  /www/server/panel/vhost/cert/example.com/privkey.pem;
```

`certDir` 填 `/www/server/panel/vhost/cert/example.com`。目录名以磁盘为准，不一定等于域名。

## 程序根据什么做决定

每一轮按 YAML 里任务的书写顺序串行执行。一条失败，后面的任务继续。

根配置读不了（YAML 坏了、缺邮箱、`schedule.hours` 不合法等）：退出码 1，不跑任务，不写 `status.json`。

单条任务：

```text
字段不合法          → 记失败，下一条
enabled: false      → 跳过
证书还很新，
且 Nginx / CDN 上次都成功  → 跳过（日志：证书仍在续签窗口外）
没有 live 证书，
或剩余天数 ≤ renewBeforeDays，
或上次签发失败      → 调用 Certbot
证书没变，
只有应用动作失败    → 不签发，只重试失败的 Nginx / CDN
```

「还很新」看数据卷里这张证书的到期时间，窗口是 `letsencrypt.renewBeforeDays`（默认 30 天，含当天）。

`--dry-run`：只做 Certbot 演练，不写 Nginx、不调 CAS/CDN、不跑钩子。DNS-01 演练时仍可能向云解析写 TXT。

时刻表（`cert-renew schedule`）：启动先跑一轮；再按 `TZ` + `schedule.hours` 睡到下次，睡前现抽 0–30 分钟。有任务失败（退出码 2）继续按时刻表跑。

## 一轮里做什么

```text
读 /config/config.yaml
        │
        ▼
按顺序处理每条任务
        │
        ├─ 需要签发？ ──是──► Certbot certonly
        │                      HTTP-01：把校验文件写到 webroot
        │                      DNS-01：钩子往阿里云解析写 TXT，等传播，再删掉
        │                      已有同一任务证书时加 --force-renewal
        │                      失败：不应用、不跑钩子
        │
        ├─ 需要应用？ ──是──► 按 apply 书写顺序
        │                      nginx：换 pem → nginx -t → reload
        │                      aliyun-cdn：上传 CAS → 按域名绑定
        │                      一个失败，同任务里后面的动作继续
        │
        └─ 这一轮真正写出新证书？ ──是──► 跑 hook.command（可省略）
                                         钩子失败不回滚 Nginx / CDN
```

证书正文在数据卷 `/var/lib/acme/letsencrypt/live/<任务id>/`。应用动作是把这份证书抄到 Nginx 目录，以及上传到阿里云。

## 怎么让 Nginx 用上新证书

不改站点 conf，不写宝塔数据库。

1. 从数据卷读 `fullchain.pem` / `privkey.pem`。目标目录不存在时会先建好。`--dry-run` 不建目录。
2. 备份 `certDir`（或 custom 路径）里已有的同名文件。
3. 覆盖写入新文件。证书 `644`，私钥 `600`。
4. `nsenter -t 1 -m -- <nginxBin> -t`。失败则还原备份，不 reload。
5. 测试通过再 `nginx -s reload`。reload 失败则还原备份，再 reload 一次回到旧证书。
6. 成功后删掉临时备份。

已经开了 HTTPS、且 `ssl_certificate` 就是这两份 pem：reload 后站点用上新证，server 块原样保留。

证书路径写成别的文件：程序仍会写 `certDir`，Nginx 继续读旧路径，站点证书不变。

还没开 HTTPS：只会多两份 pem，不会自动变成 443。

站点在 CDN 后面时，浏览器看到的是 CDN 证书。源站 Nginx 是否更新，看 `certDir` 里的文件和源站 IP 的 443。

## 怎么让阿里云用上新证书

分三段，都用官方 SDK，密钥来自 `.env`。

**DNS-01 校验（签发时，不是换 CDN 证书）**

- 按域名和 `zone` 算出主机记录，例如 `example.com` → `_acme-challenge`。
- 添加 TXT，记下 RecordId；全部挑战写完后等待 `propagationSeconds`。
- Certbot 结束后只删除本轮自己加的那条。

**数字证书管理服务（CAS）**

- 确认每个 CDN 加速域名都被这张证书覆盖（精确相等，或被一级泛域名覆盖）。有一个不符合：整段 CDN 失败，不上传。
- 证书指纹与上次相同：复用已存的 `cas.certId`，不再上传。
- 指纹变了：`UploadUserCertificate`，名称形如 `acme-<任务id>-YYYYMMDD`，重名则 `-2` … `-5`。
- 不删除 CAS 里的旧证书。

**CDN 内容分发**

- 对每个加速域名调用 `SetCdnDomainSSLCertificate`，`CertType=cas`，带上刚拿到的 CertId。
- 同指纹下已经成功的域名跳过。
- 其中一个域名失败，其它域名仍会尝试。
- 不创建加速域名，不开通 HTTPS。控制台里域名必须已经存在且已开 HTTPS。
- 第一期只做 CDN，不做 DCDN / ESA。

CDN 控制台生效可能有几分钟。对账看 `state/<任务id>.json` 里的 `cas.certId` 和 `targets["cdn:域名"].ok`。

## 程序不会做的

- 不实现 ACME，签发全部交给 Certbot
- 不扫描宝塔、不改 server 块、不回写面板数据库
- 不在机器之间拷贝证书
- 不创建 CDN 域名、不删 CAS 旧证
- 不做网页和控制机
- 不发通知

## 怎么确认这一轮

```bash
docker compose logs --tail=200 renew
docker compose exec renew cat /var/lib/acme/status.json
docker compose exec renew cat /var/lib/acme/state/<任务id>.json
```

| 日志 / 字段 | 含义 |
| --- | --- |
| 签发成功 | Certbot 写出了新证书 |
| Nginx 已重载 … | `nginx -t` 和 reload 都过了 |
| CDN 已更新 | 配置里的加速域名都绑定了这个 CertId |
| `cas.certId` / `cas.name` | 数字证书管理服务里的用户证书 |
| `targets["cdn:域名"].ok` | 该加速域名绑定成功 |
| `nginxTest` / `nginxReload` | 本轮 Nginx 测试和 reload |
